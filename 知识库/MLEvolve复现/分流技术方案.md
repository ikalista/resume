# 大模型分流技术方案

## 背景与约束
受 KV Cache 复用等特性影响，大模型负载均衡需同时满足两项相互矛盾的目标：

1. **会话亲和性**：同一用户尽量固定路由至同一模型实例，以最大化 KV Cache 命中率；
2. **Token 级均衡**：按各实例实际 token 消耗量均衡分配，而非请求数或用户数（单个高频用户的消耗可等同百名普通用户）。

两者之间需做权衡。

## 现状

litellm 现有负载均衡策略均不满足上述要求。当前方案中，litellm 仅承担模型 ID 抽象，分流逻辑由业务代码自行实现。

## 分流策略

分流涉及两类场景：

1. **新增用户**：依据当前各实例负载，按既定分配比例（如 `4:4:2`）将新用户路由至负载最低的实例；
2. **存量用户迁移**：当分配比例调整（如 `4:4:2` → `5:5:0`）时，计算最小用户迁移集合，执行有限迁移并重启对应容器。
