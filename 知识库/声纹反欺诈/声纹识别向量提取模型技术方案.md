# 背景与目标
本文讨论的是文本无关说话人识别，文本相关的说话人识别暂不在范围内。

## 项目背景
声纹识别技术应用于，**身份验证**，**黑产声纹库匹配**，**潜在欺诈风险挖掘**三个场景。

## 目标定义
### 业务目标
单用户下，识别多通对话声音不一致，发现疑似黑产用户，辅助人工策略提效。

跨用户下，识别声音相似的黑产/中介说话人，辅助人工策略提效。

6月底前上线。（业务明确有这个需求，不过实际情况要视算法迭代情况及数据集指标而定）。

### 技术目标
在开源数据集上，用开源模型复现开源数据集效果。

在业务数据集上，指标超过声扬的声纹模型，目前ERR最大差距10%（20% - 10%）。

在业务数据集上，准确率优先，95%准确率的情况下，保证30%的召回率。

在业务数据集上，正负样本比例1:1下，准召回率皆达到80% == EER低于20%。

# 算法设计
## 数据预处理
+ **数据增强**：为提高模型鲁棒性，常对训练数据进行加噪、混响、变速、变调等增强操作，以模拟真实环境中的多样性。
+ **原始语音信号**：输入可以是时域的原始波形（Raw Waveform）或经过预处理的频域特征（如MFCC、梅尔滤波器组、FBank、频谱图等）、到现代的**WavLM、HuBert，等自监督特征**。

| **特征** | **MFCC（梅尔频率倒谱系数）** | **FBank（Mel滤波器组能量）** |
| --- | --- | --- |
| **定义** | 对FBank做**DCT变换**得到的倒谱系数 | 直接计算Mel滤波器组的**对数能量** |
| **包含步骤** | 分帧→FFT→Mel滤波→取对数→DCT | 分帧→FFT→Mel滤波→取对数 |
| **信息类型** | 强调**频谱包络**（压制细节信息） | 保留更多**原始频谱细节** |
| **维度** | 通常取前12-20维（丢弃高频系数） | 保留全部滤波器组维度（如40维） |

## SOTA模型原理简述
### ECAPA-TDNN
+ **核心改进点（对比传统x-vector TDNN）**
    - **通道注意力机制（SE-Blocks）**：引入Squeeze-and-Excitation（SE）模块，动态调整通道权重，强调重要频带特征。
    - **多尺度特征提取（Res2Net）**：通过分层残差连接，捕捉不同时间尺度的语音特征。
    - **层级特征聚合（MFA）**：融合不同深度的特征图，保留浅层（音素）和深层（说话人）信息。
    - **通道依赖的统计池化**：为每个通道计算独立的注意力权重，优化全局特征的鲁棒性。
+ **AAM-Softmax损失**：
    - 使用加性角度间隔损失（Additive Angular Margin），增强类间区分性。
    - 输出192维嵌入向量（用于余弦相似度评分）。

### Cam++
+ **前端卷积模块（FCM, Front-end Convolution Module）**
    - 采用 **2D 卷积（ResNet风格）** 处理频谱特征，增强对频域变化的鲁棒性。
    - 包含 4 个残差块，逐步下采样频率维度（8x 降采样），输出扁平化后输入 D-TDNN。
+ **D-TDNN 主干网络 + 上下文感知掩码（CAM）**
    - **D-TDNN**：密集连接的 TDNN，通过跨层连接（类似 DenseNet）增强特征复用。
    - **CAM（Context-Aware Masking）**：轻量级注意力机制，动态聚焦于说话人相关特征，抑制噪声。
                    * $ 输出特征=TDNN 特征⊙CAM 掩码 $

![](https://cdn.nlark.com/yuque/0/2025/png/40685174/1744347789954-1ebbe126-83a7-4e4b-85d6-7c0465abb93e.png)

+ **性能优势**
    - **速度**：推理速度是 ECAPA-TDNN 的 **2.5 倍**（RTF=0.013 vs 0.033）
    - **精度**：在 VoxCeleb1-O 上 EER 仅 **0.73%**，优于 ECAPA-TDNN（0.89%）

### ERes2Net
+ **Bottom-up Dual-stage Feature Fusion (BDFF)**
    - **作用**：优化全局特征融合，仅保留 **Stage 3 和 Stage 4** 的特征交互（减少冗余）。
    - **方法**：
        * 对 Stage 3 特征进行 **下采样（3×3 Conv）**，再与 Stage 4 特征通过 **注意力特征融合（AFF）** 结合。
        * AFF 模块计算注意力权重，动态调整特征重要性。

![](https://cdn.nlark.com/yuque/0/2025/png/40685174/1744337804245-7c67eab9-be42-48e2-b607-62e6419cbf5e.png)

+ **Bottleneck-like Local Feature Fusion (BLFF)**
    - **作用**：增强局部特征表达能力，同时减少计算量。
    - **方法**：**扩展-压缩-扩展（Expand-Reduce-Expand）**：
            1. 先用 **1×1 Conv 扩展通道维度**（增强特征容量）。
            2. 再用 **3×3 Conv 提取局部特征**，并通过 **AFF 模块融合多尺度特征**。
            3. 最后用 **1×1 Conv 压缩回原通道数**（降低计算量）。

![](https://cdn.nlark.com/yuque/0/2025/png/40685174/1744337828685-92e6fd1f-469e-41c4-a117-7bd5f7b607c2.png)

# 详细实现方案
## 目标
1. 模型目标为将开源模型迁移学习至适应公司内部音频数据，进行公司内通话场景下的声纹识别，所以方案为：
    1. 构建内部业务数据集切分dev，test，val
    2. **基于内部业务数据集上进行各种消融实验（详情在5.2实验策略和实验设计）**
        1. 在test及val上效果一致（防止在训练数据上过拟合）
        2. 模型在开源数据集上掉点不严重（防止在内部业务数据集整体上过拟合）
        3. 在val数据集上模型指标接近开源效果（模型的有效性）
        4. 超越声扬模型效果（决定能否替换采购方案）
    3. 拉齐硬件/开发资源，模型并行进行超大数据量的推理，以及满足实时推理需求。

## 训练
### 数据来源
#### 开源数据集
**VoxCeleb**

+ 使用 **VoxCeleb2 的开发集**（`dev set`）进行训练，包含 **5,994 个说话人**的语音数据。
+ 评估时使用 **VoxCeleb1** 的三个测试子集：
    - **VoxCeleb1-O**（干净、无重叠说话人）
    - **VoxCeleb1-E**（扩展版，更多测试对）
    - **VoxCeleb1-H**（高难度，说话人身份和国籍更多样）

**<font style="color:rgb(64, 64, 64);">CN-Celeb</font>**

+ 使用 **CN-Celeb1 和 CN-Celeb2 的开发集**，包含 **2,785 个说话人**（中文场景为主）。
+ 测试时对同一说话人的多段注册语音的嵌入（embeddings）进行平均，生成最终说话人表征。

#### 业务数据集
排除疑似黑产，并且通过【tkh声音质量预处理管道】筛选后的合格录音，继续以同cust_id为同一个人为标注，收集100万通录音（可以调整）。

### 数据增强方案
1. **速度扰动（Speed Perturbation）（文本无关设计）**：
+ 随机从`{0.9, 1.0, 1.1}`中选择一个比例对音频进行变速处理，生成新样本并视为来自新说话人。
2. **模拟混响（Reverberation）**：
+ 使用RIR数据集模拟真实环境中的混响效果，生成新样本并视为来自同一说话人。
3. **添加噪声（Noise Addition）**：
+ 使用noise72、MUSAN等数据集在训练数据中添加背景噪声，生成新样本并视为来自同一说话人。
+ 针对性添加生产常见噪音，生成新样本并视为来自同一说话人，进一步增强通话场景的声纹识别。
4. **训练样本构造**：
+ 从每条音频中随机裁剪3秒长的片段用于构建训练批次（和模型训练时保持一致）。

### 训练方案
全链路的模型无关的评估脚本，在每次行动后评估，进行消融对比，输出需要关注的所有测试集的各项指标

随时分叉对数据进行下钻分析，如【上海用户的ERR较高】，【男性召回高但是准确率低】，确认问题后扩展数据集进行增强训练。

# 测试与验证
## 评测设计
评测指标：EER，MinDCF，DET，AUC，precision，recall

声纹领域下的指标，可以概况为以上指标与各类数据集的笛卡尔积。

随时对数据进行下钻分析，如【上海用户的ERR较高】，【男性召回高但是准确率低】，确认问题后扩展数据集进行增强训练。

## 实验策略和实验设计
消融顺序：增加训练数据集 -> 换模型 + 全量训练/后训练 -> 调整模型超参 ->  调整模型结构 

### 数据超参类消融实验
+ 数据集本身（目前开源2个，业务3个共5个）
    - 三个业务数据集：Simple（3万audio，3万speaker），ShengYangScore（1000万pair score），ShengYangEmb（14万audio，6万speaker）
    - 两个开源评测集：VoxCeleb， CN-Celeb/CN-Celeb2
+ 增强数据集
    - 实验：应用速度扰动，加噪，混响等增强当前数据集
    - 意义：需要增强模型的抗噪能力，以及避免模型学习到文本相关的说话人特征（如口头禅）
+ 下钻数据集
    - 实验：持续关注下钻指标的异动，如【上海人说话数据集】，【男性说话数据集】，指标下降较大时探明原因，增加训练数据。
    - 意义：模型可能在某次训练后局部最优贴近某个特定数据集，需要及时发现避免后续训练失败。
+ 采样比例（目前有两种）：
    - 实验：实验【1:1】【1:50】甚至于更多的比例
    - 意义：反欺诈领域的正例稀疏，正负样本比例经常性1:100，导致auc等指标失真，需要观察正负样本比例对于指标异动的影响。



---

### 模型超参类消融实验
+ 模型本身
    - 意义：目前声纹模型各有千秋，未一家独大，所以需要对多种SOTA模型的效果进行持续关注，最后选择最好的。
    - 实验：三个开源模型，一个外部模型，三个模型的训练版本，共7个枚举值（如再考虑模型版本则继续以3的倍数新增），持续关注各项指标。
+ 模型训练
    - 意义：开源声纹模型一般在VoxCeleb上预训练，说话人少，英文，且开源数据集简单。需要观察在VoxCeleb上的预训练对于后训练来说是有益还是有害。
    - 实验设计：全量训练，后训练。观察在开源数据集/业务数据集上的指标好坏。
+ 模型超参数
    - AAM-Softmax超参数
        * 意义：声纹/人脸识别常用的分割损失，m意味着向量的簇紧凑性，和不同类间的容忍距离。m越高类之间距离更远，由于公司内说话人数量远高于开源数据集，类也更多，类间更近，所以需要缩小m观察对指标的影响。  
![](https://cdn.nlark.com/yuque/0/2025/png/40685174/1744339161489-f240a5ab-44ab-4461-8d3c-0b4d8b1afd5d.png)
        * 实验设计：比对m = 0.1-0.3在开源+业务的2+3的数据集上的指标，输出业务集上最优的m。
    - 调整模型层数
        * 意义：开源数据集都是数千个说话人，公司内的上千万说话人，模型有必要增大以容纳更多的信息。
        * 实验设计：声纹模型都有类似于ResNetBlock的结构，翻倍block数量观察模型在业务数据集上的指标。
+ 模型结构（如有必要）：
    - Res2Net是否还有改进的可能：
        * Res2Net（基线模型）：作为基础模型，未加入任何改进模块（表3中的第一行）。
        * Res2Net + LFF（局部特征融合）：仅加入局部特征融合模块（表3中的第二行），在标准配置下，EER相对降低31.1%（VoxCeleb1-O），证明LFF对细粒度特征提取的有效性。
        * Res2Net + GFF（全局特征融合）：仅加入全局特征融合模块（表3中的第三行），EER相对降低11.2%（VoxCeleb1-O），显示GFF对多尺度特征聚合的贡献。
        * ERes2Net（LFF + GFF）：结合局部和全局特征融合（表3中的第四行），EER进一步降低至0.92%（标准配置），表明二者互补性强。
    - 实验设计：Res2Net的有4个先后的一维卷积，Enhanced Res2Net削减为两个，比对这两种结构在业务数据集上的效果。探索transformer + attention结构替换Res2Net的特征提取层。
    - 意义：探索新的模型结构。

# 风险评估与实施计划
## 风险分析
### 技术风险
理想情况：如目标是超越外部供应商，可以认为技术风险较低。因为掌握了私有的业务数据集，数据量足够大，数据质量足够好，可以不断进行消融实验来逼近更好的指标，最终目标为超越所有开源模型，也必然可以超过声扬的算法在公司内部数据上的效果。

应急预案：模型效果仍然不及预期（如数据实在脏，模型学崩了，声纹本身的局限性，人的说话口气不像指纹/虹膜一样是唯一的），从生产特征及协助决策建模等角度，退行提供辅助支持。

### 实施风险
离线推理风险：2000万通录音的数据量过大，会引发很多MLSys的问题：

+ 如2000万通录音本身需要100TB左右的磁盘空间，目前嘉定ceph都只有20T。
+ 需要模型并行及流式推理（如流水线并行，预处理好的录音应该立刻进模型，而不是等待）。
+ 录音下载分发，模型并行等需要的网络传输开销大。
+ 业务部门要的太急，deadline为6月底，有可能出现模型效果不足仓促上线的情况。

在线推理风险：

+ 需要向量库支持大数据量的相似度计算，或大内存/显存应用进行矩阵相似度计算。
+ 3倍冗余应对并发最高峰，需要显卡硬件支持。
+ 需要考虑高并发下的batching。

### 资源分配：
推理性能上，cam++ > ERes2Net = ECAPA



离线跑批 - 以cam++为例batch_size=64，模型6G，数据6G，吞吐量1万条/h。单卡可以承担*10，吞吐量10万条/h

Cam++，回溯7000万条语音，需要7000万/10万/ = 700h * A100（理论值）

Cam++，每日向量化30万条语音，需要30万/10万/ = 3h * A100（理论值）



实时推理 - 以cam++为例贷后180，外呼200，冗余1.5倍，共550并发。假设每通电话10s：550*3600/10 = 20万/h，=2 * A100



即需要1张A100训练，一张A100或2*A40推理
