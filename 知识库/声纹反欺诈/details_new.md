# 项目背景
## 背景：
截至今年第一季度，黑灰产市场规模已急剧扩大至2800亿元。

这个数字背后，是越来越多的中介在抖音、快手、小红书等平台，利用用户逾期的焦虑情绪，以“债务重组”“代理维权”“退费”等名义吸引用户、实施诈骗。

天下没有免费的午餐，黑产中介的每一次“成功”，本质上都是在对助贷公司进行吸血。他们的攻击手段不断升级（如承诺用户公司内有人，100%退款、伪造材料、二次收费），直接导致了我们和用户共同的两方面的损失：

第一重收割：截流还款能力，推高坏账率：用户的资金是有限的。中介通过“高退费承诺”诱导用户，抽取20%甚至高达50%的手续费。这笔钱本应是用户用于偿还我们欠款的资金，却被中介截留。中介抽成越狠，用户对我们的实际还款能力就越弱，甚至被“二次收费”彻底榨干变为死账。中介赚的每一分钱，都可能成为我们无法回收的坏账。

第二重收割：伪造证据骗赔，造成直接资损：这也是对公司利益伤害很大的一环。为了达成“停账”，“退费”等目的，中介教唆甚至直接帮用户伪造病历、贫困证明等材料，欺诈性地突破我们的退费/减免红线。 这导致我们支付不合理的退费，或进行了错误的债务减免。黑产通过欺诈手段，将我们的合规让步转化为他们的非法利润，直接造成了公司的现金流失。

因此，声纹的目标，也是反欺诈的目标，就是发现中介及黑产，进行差异化处置。避免无效的退费支出，并将流失的资金转化为我们的回收款，实现公司止损。避免没有中间商赚差价。

为了及时的发现他们，传统的反欺诈基于结构化特征，像基于年龄、户籍、三方分等，随着时间的发展，效果已经减弱了。在这个节点上，我们急需寻找一些新的方法去发现他们。

幸运的是，我们正处于一个技术爆发的前夜。
随着近期多模态大模型能力的井喷式增长，AI对非结构化数据的理解能力突然跨过了一个‘奇点’。无论是用户上传的图片，还是我们库里沉淀的海量录音，这些曾经难以利用的数据，现在都成了我们可以挖掘的金矿。

## 整体架构
（手势指引：先圈出架构图中间的"反欺诈能力"两块蓝色大区域）

多模态反欺诈架构分为两个核心场景，黑产欺诈和个人/合谋欺诈：

左侧'黑产欺诈'：针对中介和团伙，利用声纹的唯一性和稳定性进行黑产声纹库建设。核心逻辑是同一个人无论使用哪个手机号或账号，声纹特征基本不变。一旦某个声音被确认为黑产中介，系统就能在后续所有通话中实时识别并预警。

业务价值则在于'精准识别，关联打击'：通过声纹比对，将表面分散、使用不同账号的攻击行为关联到同一人身上，实现批量打击和根源降损。

右侧'个人合谋欺诈'：识别非本人进行或有人指导合谋欺诈的情况。目标是差异化处理+提效，赋能客服识别通话风险。对真实用户可以放宽条件节省通时，对高风险通话辅助人工审核，提升反欺诈响应速度。

（手势指引：视线下移，聚焦到'数据处理Pipeline'）
支撑这两大能力的底座，是我们基于开源模型自研的高性能的全链路声音处理管线。原始录音很'脏'，我们进行'拆解'→ 分离客户与客服声道，'清洗'→ 降噪 + 人声提取，去掉环境杂音  '提炼'→ 声纹Embedding，转化为数学向量

这套自研流程成本仅为外采的十分之一，效果接近专业的外部供应商，建立起自主可控的反欺诈能力壁垒。

2. “第二个战场，我们聚焦于‘实时核身’。这里的核心挑战非常直接：如何在与用户交互的‘黄金20秒’内，快速、无感地判断‘电话那头是不是本人’？

2.1. 场景与痛点
想想那些高风险场景：中介代客进线谈判，或在旁教唆。
传统的核身方式，要么是一连串繁琐的知识问答（‘您好是李嘉辉本人吗，您身份证后4位是多少？’）必要时还会拉起视频验证，耗时且体验差；以上情况用户只要提供文件协助在旁边配合，就能破解这套验证手段。
而声纹核身，提供了一种更本质的解法：它不再问‘你知道什么’，而是通过声音特征直接验证‘你是不是你’。

----------------------------------------------------------------------------------------------------

2.2. 案例演示与识别难点

我们来看一个案例。（展示A用户的历史通话声纹分布图）
假设这是用户A的三次历史进线记录：
前两次（A1、A2）是本人进线，声纹高度一致；
第三次（A3）是中介进线，声纹差异巨大。

经过声纹模型后，我们发现声纹A1和A2非常相似，A3则有着很大的区别。在声纹距离上，A3离A1和A2非常遥远。
因此在用户A的的A3进线时，个人声纹核身就会告警给作业中的客服人员：此通非本人！客服就可以进行特殊处置，如变的强硬但话术敏感（避免被抓把柄），要求本人进行沟通，。

这里还有另一个隐藏的挑战点，现在只有3通通话，当用户第4次，甚至于第100次进线时，系统该怎么判断？

如果是离线场景，我们可以把第四次声音和前三次逐一比对。但在实时通话场景下，如果用户历史积累了上百通录音，全量逐一比对会导致系统高延迟，根本无法满足实时的响应要求。

2.3. 核心策略：‘聚类投票’，确认个人声纹。
“这里隐藏着一个技术挑战：随着时间推移，用户的历史录音可能成百上千。如果在实时通话中逐一比对，系统会卡顿，‘黄金20秒’将荡然无存。 为了解决这个问题，我们采用了一种聪明的策略：从历史声纹中，聚类投票出本人声纹，线上实时进线时只进行1:1比对。

它的原理非常直观： 想象一下，虽然用户有过中介代打（如A3），但把时间拉长，出现频率最高、最稳定的那个声音，一定是他本人。

因此，系统不再盲目比对每一条录音，而是先在后台做一次‘大清洗’： 它将所有历史声音放在一起进行**‘聚类’，像筛选豆子一样，把那些偶尔出现的‘杂音’（中介、噪音），以及和黑产有关的录音，剔除出去。最后，在剩下来最大的一堆‘真声’里，选出一个最能代表他的声音，作为唯一的‘声音指纹’**存入库中。

效果立竿见影： 当用户再次进线时，我们不需要翻阅几百条历史记录，只需拿新声音和这个唯一的‘声音指纹’做 1:1 比对。 总结来说，这个方案用算法解决了‘数据提纯’的问题，用聚类投票解决了‘计算速度’的问题。用户简单的聊两句的时间内，就已经在毫秒间确认了——‘你就是你’。”

## 挑战1 如何清洗干净的录音？
首当其冲的：生产的通话录音总是千奇百怪的，坐席客户声音混杂，振铃声没有剥离，客户在外面噪音很大，客户不说话怎么办？
通过客户声道分离、dfmns模型降噪，VAD人声提取，最终获取到用户的干净人声（放录音）。具体技术要点：
- 客户声道分离
- 振铃检测与去除 -> 0.21 -> 0.19
- 降噪 -> 0.19 -> 0.1688
- 人声提取：去静音 → VAD检测，去除空音: 评估指标：IOU，precision，recall  -> 0.1688 -> 0.13
- 声纹提取： Camplus -> Eres2NetV2 评估指标：EER，0.13-> 0.11，从27%优化至13%，接近声扬的11%

## 挑战3 ：大规模embedding相似度计算
采用分块并行策略，将400万×400万矩阵拆解为可调度计算单元。

声纹提取完成了，但我们距离真正的目标还有关键一步要走：【判断两通通话是否相似】。我们先看规模：光是最小规模的客服侧数据，近半年就有400万通通话。如果直接做全量两两比对，需要存储 400万 × 400万 的相似度矩阵，光是存储中间结果就需 64TB 显存——这相当于约 800 张 A100 显卡，成本几乎抵得上嘉银去年利润的 10%。显然，直接计算既不现实，也不经济。

该问题的常见解法是将巨大的矩阵乘法分块为多个小矩阵相乘。400万*400万，分成1600个， 10万 × 10万 的任务。这样不仅把计算规模降到了资源可承受的范围，更天然实现了并行化——任务被抽象为无状态（Stateless）且独立的任务，可以交给大数据集群自行进行分布式潮汐调度。

这种设计让我们在有限资源下，依然能稳定、灵活地推进大规模声纹相似度计算，最后通过离线聚类及在线聚类，进而赋能业务的事中预警/事后分析。
