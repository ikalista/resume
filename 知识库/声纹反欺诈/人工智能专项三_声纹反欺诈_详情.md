# 业务痛点
1. **技术能力空白**：嘉银在声音反欺诈、身份核验及风控等业务领域尚未建立相关技术能力，面对海量录音数据（总量7000万条，有效数据2600万条），传统人工分析方式无法满足业务需求
2. **反欺诈**: 针对黑产用户/团伙进行甄别进而降低运营成本。
3. **数据价值未充分挖掘**：缺乏声纹身份标识（VID）体系，无法有效融合结构化数据与声音模态特征，声纹特征库建设不完善

# 目标
业务目标：
1. 构建文本无关说话人识别系统，支撑**身份验证**、**黑产声纹库匹配**和**声音模态特征数据挖掘**等业务场景
2. 身份验证：在单用户维度下，识别多通对话中的声音不一致情况，发现疑似黑产用户
3. 黑产声纹库匹配：在跨用户维度下，识别声音相似的黑产/中介说话人
4. 声音模态特征数据挖掘：提取用户声音特征，构建声纹特征库
5. 建立声纹身份标识（VID），融合结构化数据与声音模态特征

技术目标：
1. 在业务数据集上，EER低于10%（当前水位20%），90%准确率下召回率≥30%
2. 630前完成存量2600万通录音的裁剪与向量提取，需要处理100万录音/天

# 技术痛点
1. 裁剪链路过长，导致串行的耗时较高（10-12s），急需降低单条耗时以提升跑批效率。
2. 降噪模型耗时较高(8-10s)，原生无法batching，急需并行方法降低摊销耗时。
    - 降噪模型修改源码进行批处理实验，padding不同的录音至最长，发现摊销下来更慢。
    - 降噪模型进行模型并行，多进程增加并行度将耗时摊销降下来。
3. 需要的计算资源较高，**9台机器**共**800C 800G**+**8*A30显卡**进行**CPU/GPU**混合推理，资源调度及分配极为复杂，需要设计一种算法分配资源进行高效推理。
4. 运行时长较长，需要稳定的运行及重试机制来保证整个链路的稳定运行：
    - oss在高频次下访问会超时，设计重试机制保障原子进程的稳定性
    - 在表极大的情况下，sql会非常耗时，优化索引及sql将2s提速至0.07s，打碎取数瓶颈
    - 模型推理预加载，将耗时由千条1000s降低至500s
    - 搭建监控机器人，实时监控跑批运行状态

# 关键事项及进展
1. 模型选型：输出SOTA开源模型在各数据集上的水位
    - （已完成）ECAPA-TDNN：英文训练，使用广泛，(TDNN系列)
    - （已完成）ERes2Net：中英文训练，效果最好，参数较多(17.8M+)，(Res2Net系列)
    - （已完成）CAM++：中英文训练，参数少(7.18M)，速度快(2.5倍于ECAPA)(TDNN系列)
    - （进行中）ReDimNet: 最新的SOTA模型 (ReDimNet系列)

2. 离线推理性能优化：链路长, 模型多, cpu/gpu混合推理
    - （已完成）流批一体化项目结构设计, 良好的架构设计提升整体迭代效率
    - （已完成）数据库慢SQL优化：建立复合索引，录音元数据查询从2s优化至200ms
    - （已完成）降噪模型并行优化：降噪模型多进程并行处理，提升400%吞吐，将单挑推理摊销至2s/条
    - （已完成）流水线推理优化：音频预处理、特征提取等九阶段流水线并行，将串行的8-10s降低至降噪瓶颈处的2s，整体吞吐量由10万/天提升至90万/天
    - （进行中）大pod实验，增加降噪并行度降低其他环节的并行度，来尝试提速

3. 数据增强策略
    - （待开始）速度扰动(0.9-1.1)以实现文本无关训练
    - （待开始）添加噪声增强抗噪能力

    - （待开始）随机裁剪3秒片段构建训练批次

4. 消融实验设计
    - （进行中）数据集扩充：业务数据集(2000万通录音)+开源数据集
    - （待开始）训练策略：增量训练、全量训练、模型结构优化

# 衡量指标
1. EER(Equal Error Rate)：正负样本比例1:1下低于10%
2. 准确率/召回率：90%准确率下召回率≥30%
3. 跨数据集表现：开源数据集上保持效果，业务数据集上明显提升

# 风险
1. 技术风险：模型效果不及预期，人声纹不如指纹/虹膜唯一
2. 实施风险

    - 硬件需求：9台机器的CPU/GPU混合推理，1张A100或2*L40推理
    - 时间紧迫：630完成存量跑批
